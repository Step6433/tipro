# Tipro — онлайн-чаевые

Связанное MVP: существующий Vue 3-фронтенд + FastAPI + PostgreSQL. Гость сканирует QR ресторана, выбирает сотрудника и оставляет демочаевые. Сотрудник видит свои платежи и цели, менеджер — команду и статистику ресторана, администратор — всю платформу.

Деньги не списываются. Вместо localStorage приложение использует реальный REST API и PostgreSQL. Дизайн сохранён; добавлены необходимые настройки валюты/процентов и состояние ожидания оплаты.

## Запуск в текущей папке

Выполненные настройки и команды установки с нуля подробно описаны в [backend/README.md](backend/README.md).

**Двойной щелчок по файлу `Запустить Tipro.command` в Finder** — база, миграции, FastAPI и Vue запускаются автоматически, затем открывается браузер. Если macOS попросит выбрать приложение для `.command`, выберите Terminal.

Из терминала или встроенного терминала IDE достаточно одной команды:

```sh
npm start
```

Оставьте окно запуска открытым. Для остановки нажмите **Ctrl+C**: завершатся только серверы, запущенные этим окном; PostgreSQL и уже работавшие серверы останутся запущенными. Повторный запуск использует работающее приложение. Секреты, данные и демоаккаунты при старте не перезаписываются, seed автоматически не запускается.

Лаунчер рассчитан на уже настроенное окружение этого Mac. Он находит локальную PostgreSQL автоматически; если временные бинарники были удалены, установите PostgreSQL 18 и укажите путь через `TIPRO_PG_BIN=/путь/к/bin npm start`. На новом компьютере сначала выполните первоначальную установку ниже. При запуске автоматически определяется локальный IPv4; для выбора другого сетевого интерфейса задайте `TIPRO_LAN_HOST=192.168.2.147 npm start`. Для запуска без открытия браузера: `npm start -- --no-open`.

Раздельные команды `npm run dev:api` и `npm run dev` также доступны.

Лаунчер показывает и открывает адрес сайта в локальной сети, например `http://192.168.2.147:5173`. На самом Mac также доступен http://localhost:5173. Swagger: http://127.0.0.1:8000/docs. Vite проксирует `/api` на FastAPI.

В этой рабочей среде дамп `/Users/stepan/Downloads/Users.sql` уже восстановлен в отдельную PostgreSQL 18 на `127.0.0.1:55432`. Пользовательские системные базы не менялись. Для повторного старта этой отдельной БД, если она остановлена:

```sh
backend/.venv/bin/python backend/scripts/local_postgres.py --bin-dir /private/tmp/tipro-postgres18/bin
```

Временные бинарники могут быть удалены ОС; тогда используйте установленную PostgreSQL 18 или [Docker-инструкцию](backend/README.md#docker-compose). Файлы БД находятся в игнорируемом `backend/.runtime/pgdata`.

## Открыть QR с телефона

1. Подключите Mac и телефон к одной сети Wi-Fi и запустите `Запустить Tipro.command` либо `npm start`.
2. Откройте адрес, показанный лаунчером, войдите менеджером и откройте «QR-код». Обновите страницу, если она была открыта до перезапуска.
3. Сканируйте актуальный QR камерой телефона: он содержит сетевой адрес Mac и открывает страницу ресторана без регистрации гостя. Ранее скачанные изображения с `localhost` нужно скачать заново.

Лаунчер передаёт найденный адрес в `FRONTEND_URL` и добавляет его в доверенные Origin только на время запуска; секреты в `.env` не меняются. Vue доступен в локальной сети, API и PostgreSQL остаются на loopback; запросы телефона к `/api` проходят через прокси Vue. Если открыто старое окно запуска, сначала остановите его через Ctrl+C и запустите снова.

На телефоне можно сначала открыть показанный адрес вручную. Если он недоступен, проверьте Wi-Fi, разрешение входящих подключений Node.js в брандмауэре macOS и отсутствие изоляции устройств в гостевой сети. VPN может мешать локальному соединению. Через мобильный интернет этот локальный адрес не работает: для демонстрации вне Wi-Fi нужен отдельный публичный хостинг. QR постоянный: не истекает и не меняется после успешной оплаты. При смене IP Mac старый сетевой адрес в сохранённом PNG перестаёт работать; для неизменного адреса нужен постоянный IP или домен.

## Демоаккаунты

**Текущее локальное состояние:** база возвращена к данным исходного Users.sql: 20 ресторанов, 60 сотрудников, 100 платежей, 100 исторических QR. Миграции приложения применены. Дополнительные аккаунты и демоданные удалены; seed автоматически не запускается. Используйте исходный аккаунт либо зарегистрируйте новый. Ниже перечислены аккаунты, которые можно создать отдельным запуском seed, если снова понадобятся демоданные.

Пароль демоаккаунтов сгенерирован в **`backend/.env`, поле `DEMO_PASSWORD`**. Он не включён в исходники. Прежние аккаунты браузерного мока не являются аккаунтами PostgreSQL.

| Роль | Логин |
| --- | --- |
| Менеджер Бангкока | `manager1@tipro.example.com` |
| Менеджер Сингапура | `manager2@tipro.example.com` |
| Менеджер Ханоя | `manager3@tipro.example.com` |
| Сотрудник Бангкока | `worker11@tipro.example.com` |
| Администратор платформы | `admin@tipro.example.com` |

1. Войти менеджером → «Команда» → добавить сотрудника → передать ему приглашение.
2. Сотрудник регистрируется по одноразовой ссылке и создаёт цель в своём кабинете.
3. Менеджер один раз создаёт QR ресторана и скачивает PNG; код открывает публичную страницу ресторана.
4. Гость выбирает сотрудника, сумму или процент от чека и проводит демооплату без аккаунта.
5. Сервер подтверждает исход; запись появляется в PostgreSQL, статистике и цели сотрудника соответствующей валюты.

Настройки ресторана поддерживают язык и проценты чаевых. Выбор валюты убран из всех форм и кабинетов; внутри базы каждая запись сохраняет свою валюту. Статистика разделяется по валютам. Моковый банк поддерживает успех, отказ, отмену и ожидание; незавершённый платёж можно проверить или отменить. QR содержит подписанный токен, действует без ограничения срока и сохраняется после оплаты. Можно скачать только QR в PNG; создание и печать чеков убраны из интерфейса. После успешной оплаты гость видит благодарность без переходов на платформу. Фискальная касса и реальные банки не подключены.

## Язык интерфейса

Вверху главной, входа, кабинета и страницы оплаты есть переключатель **Русский / English / 中文**. Он переводит интерфейс сразу и сохраняет выбор в этом браузере. Даты и денежные суммы форматируются для выбранного языка; имена людей, названия ресторанов и тексты целей остаются авторскими.

В «Настройки» менеджер задаёт язык гостевой страницы по умолчанию. Личный язык кабинета меняется верхним переключателем. Выбор валюты полностью убран из интерфейса. Новые QR и цели автоматически используют валюту ресторана, а существующие записи сохраняют свои суммы и валюты.

## Где находится база данных

Рабочие данные PostgreSQL уже находятся внутри проекта в `backend/.runtime/pgdata`. Для обычного запуска используйте `npm start`.

Полная актуальная SQL-структура добавлена в [backend/schema/tipro.sql](backend/schema/tipro.sql), инструкция по переносу — [backend/schema/README.md](backend/schema/README.md). Структура включает все таблицы, связи, индексы и версию миграций, без пользовательских записей и секретов. Для демонстрационных данных есть отдельный seed. Обновить SQL-снимок: `npm run db:schema`. Каталог рабочей базы и `.env` остаются локальными и исключены из Git.

## Установка на другом компьютере

```sh
npm install
python3.12 -m venv backend/.venv
backend/.venv/bin/python -m pip install -r backend/requirements.lock
backend/.venv/bin/python backend/scripts/init_env.py
```

Далее настройте PostgreSQL в `backend/.env`, восстановите дамп **через `pg_restore`** в пустую базу, примените миграции и запустите seed:

```sh
cd backend
.venv/bin/alembic upgrade head
.venv/bin/python -m app.seed
```

Можно начать с пустой PostgreSQL без дампа: базовая миграция создаёт те же исходные таблицы. Подробности по структуре, безопасному импорту, валюте старых платежей, ролям, переменным окружения и Docker — в [инструкции бэкенда](backend/README.md).

## Проверки

```sh
npm run test:backend  # интеграционные тесты на отдельной PostgreSQL-базе
npm run build        # сборка Vue
npm run check:api    # сквозной сценарий через реальный JS API-клиент; нужен работающий API и seed
npm test             # исторические тесты старого мока, отдельно от рабочего приложения
```

`check:api` добавляет демоцель и платёж 12.50 THB тестовому сотруднику и проверяет обновление статистики и CSV. `pytest` не очищает рабочую БД: создаёт и удаляет только отдельную случайную тестовую базу.

## Структура

```text
backend/
  app/             # FastAPI, модели, роли, провайдер, REST, аналитика
  alembic/         # миграции исходной PostgreSQL-схемы
  schema/          # исходная структура без приватного дампа и данных
  scripts/         # окружение, изолированная БД, подписанный demo webhook
  tests/           # проверки на PostgreSQL
src/
  api/http.js      # HTTP, JWT в памяти, cookie-сессия, ошибки
  api/rest.js      # адаптер существующих Vue-экранов к FastAPI
  api/mock.js      # сохранён для исторических тестов, приложение его не использует
  stores/          # данные текущего аккаунта, валюта, серверная статистика
  views/           # существующие страницы + настройки ресторана
  components/      # QR, таблица, график, цели
  utils/           # валюты, суммы, даты и PNG чека
scripts/check-api.mjs # сквозная проверка того же адаптера, что использует Vue
docker-compose.yml   # PostgreSQL 18 и FastAPI
```

Секреты, исходный дамп, `.venv`, данные PostgreSQL, `node_modules` и `dist` исключены из Git. Никогда не публикуйте `backend/.env`.
