# База данных Tipro

Рабочая база уже входит в локальную папку проекта: файлы PostgreSQL находятся в `backend/.runtime/pgdata`. Приложение работает именно с PostgreSQL. При обычном запуске `npm start` подключает её автоматически. Текущие рабочие данные восстановлены из исходного Users.sql: 20 ресторанов, 60 сотрудников, 100 платежей и 100 исторических QR; миграции приложения применены, добавленных демоданных нет. Резервная копия состояния до восстановления сохранена локально в `backend/.runtime/backups`.

В исходниках находятся:

- **`tipro.sql`** — полная актуальная структура PostgreSQL 18: рестораны, сотрудники, платежи, QR, цели, сессии, события webhook, служебные таблицы, индексы, ограничения и версия миграций. Файл не содержит аккаунтов, паролей, токенов и истории платежей. Служебная строка версии Alembic включена, чтобы последующие миграции не создавали уже существующие таблицы повторно.
- `legacy.sql` — исходная структура из Users.sql до изменений приложения.
- `../alembic/versions/` — история всех изменений структуры.
- `../app/seed.py` — отдельное идемпотентное заполнение демонстрационными данными.

## Создать базу с нуля

Основной способ — создать пустую PostgreSQL, настроить `backend/.env`, затем применить миграции:

```sh
cd backend
.venv/bin/alembic upgrade head
.venv/bin/python -m app.seed
```

## Восстановить SQL-структуру на другом компьютере

Альтернативный способ — импортировать `tipro.sql` в **новую пустую** PostgreSQL 18. Из корня проекта, подставив свои адрес, имя пользователя и имя новой БД:

```sh
createdb -h localhost -U tipro tipro
psql -h localhost -U tipro -d tipro -v ON_ERROR_STOP=1 --single-transaction -f backend/schema/tipro.sql
```

Пароль вводится средствами PostgreSQL. После импорта настройте `DATABASE_URL` в `backend/.env` и выполните обычные команды миграций и seed выше. Seed заполняет только демоданные и не восстанавливает пользовательские аккаунты или платежи.

Оба способа дают одну структуру, не нужно импортировать `legacy.sql` поверх `tipro.sql`. Не импортируйте структуру поверх действующей базы с данными.

## Обновить SQL-файл после изменения моделей и миграций

После `alembic upgrade head` из корня:

```sh
npm run db:schema
```

Скрипт экспортирует только структуру и версию миграции; рабочие записи не попадают в SQL. Если pg_dump установлен в другой папке:

```sh
TIPRO_PG_BIN=/путь/к/postgresql/bin npm run db:schema
```

Каталог `backend/.runtime/pgdata` и файл `.env` исключены из Git. Бинарный каталог PostgreSQL нельзя использовать как переносимый SQL-дамп: для переноса реальных записей нужна отдельная приватная резервная копия. Исходный Users.sql и данные пользователей в SQL-структуру не включаются.
